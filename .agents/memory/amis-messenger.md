# AMIS unified messenger

- ONE shared Messenger component (variant prop: full / embedded / widget) powers every chat surface. **Why:** three divergent messenger UIs confused the owner; unifying them removed surface-specific drift. **How to apply:** never fork a per-surface messenger — extend the shared component.
- Explicit full Messenger links must remain full Messenger even on slow networks, Save-Data, or operator referrals; Lite messaging remains an explicit separate destination. **Why:** automatic Lite redirects removed access to existing conversation tools and were experienced as a broken messaging tab.
- Do not reintroduce an account device-count ceiling or silently retire encryption identities. **Why:** the owner explicitly rejected the eight-device enrollment barrier after repeated production failures. **How to apply:** bound payload sizes and rate-limit requests instead; preserve private keys, keep device revocation explicit, and treat identity conflicts as terminal rather than retrying or replacing keys.
- AMIS messages and attachments are end-to-end encrypted in the browser; private RSA keys stay non-extractable in IndexedDB and the server stores only per-device public keys plus opaque AES-GCM envelopes. Legacy plaintext messages remain readable. **Why:** the owner required real browser-side E2EE, not server-encrypted marketing copy. **How to apply:** never send new message or attachment plaintext through messaging APIs and never reintroduce the old “encrypted via server” label. Optional AI text sharing is a separate, explicitly disclosed consent boundary, not part of encrypted delivery.
- Preserve historical numeric conversation IDs when enforcing one conversation per citizen pair. **Why:** the owner's sorted-pair request describes shared identity across surfaces, not authorization to replace existing rooms and lose their history. **How to apply:** use the pair for serialization and lookup across every creation path; never migrate room IDs merely to match pseudocode.
- Citizen AI assistance must not impersonate an absent recipient or silently inspect encrypted conversations. **Why:** the owner requested five-minute intermediary assistance and translation while the platform already promised E2EE. **How to apply:** offer sender-reviewed drafts; translation is off by default, separately consented, and explains that selected plaintext leaves E2EE. Lack of a reply is not evidence that the recipient is busy.
- Every browser is a separate E2EE device. Envelopes must wrap for the exact registered device/fingerprint set, and registration/revocation, membership changes, key validation, and encrypted insertion must share database serialization. **Why:** user-level keys break multi-device access and unlocked checks persist stale-key ciphertext. **How to apply:** retain explicit inventory/revocation without age-based deletion or an account-count cap; keep encrypted payloads bounded.
- Single-pane surfaces (widget/mobile) must show exactly one pane; overlays (history/settings) live in the chat pane, so the sidebar must yield or the overlay renders zero-width.
- Call-history logging must live in the single call hook/provider, never in a chat component — the messenger can be mounted on multiple surfaces at once and would double-log. "Answered" requires an actual active transition; ring duration is not evidence of an answer.
- Messenger mute/settings columns were added by raw DDL, not the drizzle schema — query them via the pg pool, and keep new one-off columns out of drizzle unless regenerating lib/db types.
- WhatsApp-style layout is the owner-approved shape: 4 fixed destinations (Chats | Calls | Communities | Settings), navigable by tap or one deliberate horizontal swipe; Solidarity Relay lives inside Communities. **Why:** the owner wants each section isolated with its own tools. The full chat MUST stay portaled to document.body so the site navbar cannot bleed through; GIPHY/GIF remains removed.
- Mobile keyboard stability: viewport meta needs `interactive-widget=resizes-content`; composer textarea is dir="auto" at 16px (prevents iOS zoom + renders Arabic RTL correctly).
- Async hygiene: message fetch/send commits must be guarded by an active-room ref (stale responses leaked another room's conversation), and MediaRecorder + its stream must be torn down on unmount or the mic stays live.
- Settings toggles must map to real behavior (notifications → floating-button badge; read receipts = privacy pref) — a persisted-but-inert toggle gets rejected in review.
- Actus is the Solidarity Relay: completion counters track every genuine contribution, but XP/score rewards are capped to one creator and one supporter reward per citizen per UTC day. **Why:** per-initiative uniqueness still let a fixed cohort farm new initiatives. **How to apply:** serialize completion and grant points only after an atomic daily reward-ledger insert.
- The dedicated `/messages` surface must suppress global AMIS/AI floating launchers, while embedded and widget variants keep them. **Why:** fixed launchers overlapped the mobile composer and initiative forms.
- `/social` is the communication-network overview: it aggregates live status and launches existing AMIS, Pulse, events, citizens, friends, and search surfaces without deleting or relocating their tools. **Why:** the owner wants one discoverable communication future, but explicitly rejected removing sections. **How to apply:** add new channels to the overview while preserving their dedicated routes and existing tabs.
- Messenger has one attachment entry point: the standalone photo/video icon is removed, and the `+` share menu contains gallery, camera, contacts, location, files, multiple links, external-app sharing, voice, emoji, and paste. **Why:** the owner explicitly replaced the earlier split-control direction to eliminate the standalone gallery icon. **How to apply:** keep gallery/camera inside `+` and do not restore a separate composer gallery button.
