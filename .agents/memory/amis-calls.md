---
name: AMIS call system
description: Direct Agora call-provider decision, TURN diagnostics, and authoritative signaling constraints
---

- Use direct authenticated Agora for one-to-one calls, not WebRTC-first fallback. **Why:** the owner's later full-flow request on 2026-09-17 explicitly requires the caller to join Agora after saving the invitation, superseding the earlier hybrid-first request. **How to apply:** persist the invitation before token/join/media; the callee joins that same channel only after Answer. Keep existing Hetzner relay credentials separate from Agora channel tokens. Hybrid remains an explicit compatibility mode, not the selected default.
- Pre-dial diagnostics must test the selected provider. **Why:** legacy Agora last-mile metrics do not establish WebRTC/TURN readiness, and ICE candidates alone do not prove working audio/video. **How to apply:** distinguish reachability, authenticated allocation, relay traffic, and actual media verification; never present one as proof of another.
- Key call-socket lifecycle dependencies to stable account identity, not the whole user object. **Why:** a media-switch callback depending on a recreated user object repeatedly tore down sockets; cleanup state updates caused a render loop and exhausted memory in verification. **How to apply:** audit transitive callback dependencies when adding socket handlers, and test rerenders with equivalent but newly allocated account objects.
- Agora channel = crypto-random call id; certificate-backed, participant-scoped tokens are mandatory and missing credentials must fail explicitly—never fall back to tokenless App-ID mode. **Why:** predictable channels or tokenless joins let strangers eavesdrop. **How to apply:** every Agora surface fetches its token from the authenticated backend and keeps the App Certificate server-side.
- Production token configuration must be read from runtime `process.env` on each token request, and the browser must obtain a complete signed token before creating AgoraRTC; retry transient 503 readiness responses. **Why:** deployment secret injection can briefly be unavailable, and module-level snapshots or client-first startup produce “channel closed before secrets service was ready.”
- Call media uses Agora `aes-256-gcm2` with a browser-generated secret RSA-wrapped for every active callee device; all peers derive the required 32-byte public salt from the call channel. The signaling server validates the exact device fingerprints but never receives the clear media secret. **Why:** multi-device ringing and real media E2EE both failed when only one user-level key or no GCM2 salt was used.
- Agora tracks are bridged to the existing MediaStream-based call UI rather than Agora's play() API, so UI components stay transport-agnostic.
- Realtime signaling must stay under the `/api` path prefix — the production router only forwards `/api/*`; anything else silently hits the static frontend. Identity on the socket is always session-derived server-side, and the server only relays answer/reject/end for calls it saw offered, between the recorded participants.
- Client rule: answer failures must notify the caller and tear down media so the UI recovers to idle; "answered" in call history requires an actual active transition (ring time is not an answer).
- FCM is optional and may be disabled without blocking calls. **Why:** on 2026-09-17 the owner explicitly chose Agora/TURN calls without Firebase rather than supplying an Admin credential, superseding mandatory off-site push. **How to apply:** never gate calling on push readiness or request credentials unprompted; explain that disabled FCM means no closed-app push ringing.
- The caller acquires media at dial time; Agora token issuance follows durable invitation creation so tokens remain participant-scoped. The callee must explicitly Answer before acquiring media or joining. **Why:** the owner requested immediate caller media and token-backed Agora without credit gates; recipient consent remains mandatory. **How to apply:** never weaken token authorization to satisfy a token-before-invitation sequence.
- Use the existing PostgreSQL database for durable call lifecycle and replayable signaling, independent of optional Firebase. **Why:** on 2026-09-17 the owner explicitly required calling without Firebase; this supersedes Firestore-only authority but not cross-server durability. **How to apply:** preserve transactional answer/device ownership and replay; never substitute instance-local call state or delete legacy Firestore data.
- Notification actions retain explicit consent and invitation expiry. **Why:** the owner approved Answer/Decline but not automatic answering. **How to apply:** body clicks never auto-answer; actions require a live authenticated invitation, and missed notifications stay passive.
- Treat durable state replay separately from media-provider migration. **Why:** replaying an ordinary Agora acceptance during callee setup incorrectly invoked hybrid migration before decryption, producing a false missing-key error during otherwise working calls. **How to apply:** state synchronization must not recreate a media client; migration requires an actual transport change, and media consent remains independent.
