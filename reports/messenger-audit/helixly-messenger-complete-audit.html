5. مسارات البيانات: ماذا يحدث عند الضغط؟

النص

جلسة المستخدم → التحقق من الغرفة ومفاتيح أجهزة المستلمين → تشفير محلي → POST send → التحقق من المرسل والعضوية/الحظر → حفظ dm_messages → بث /api/ws → فك التشفير على جهاز المستلم → تحديث مؤشر القراءة عند العرض. لا تعني الاستجابة 201 أن المستخدم قرأ الرسالة.

الصورة/الفيديو/الملف/الصوت

اختيار/تسجيل → فحص الحجم → AES-GCM في المتصفح → start مصادق عليه للغرفة → تذكرة خادم ورابط مؤقت → PUT واحد للـciphertext مع If-None-Match → complete يتحقق من حجم ونوع الكائن → إرسال metadata مشفّرة في الرسالة → قراءة خاصة عبر /api/messages/files → فك محلي → عرض. الرابط العام غير مطلوب ولا تُرفع المفاتيح الخاصة إلى R2.

مكالمة التطبيق

زر الهاتف/الكاميرا → startCall → إشارات وحالة مصادق عليهما → رنين واجهة/إشعار بحسب حالة المستلم → قبول صريح → طلب صلاحيات وسائط/token للمشارك → جلسة Agora أو مسار الوسائط المحدد → إنهاء وتسجيل النتيجة. تشفير رسائل AES-GCM لا يثبت E2EE للمكالمة الصوتية.

خارج التطبيق

تسجيل جهاز native مصادق عليه → إرسال FCM → استلام background handler أو تشغيل native → التحقق من المكالمة والمستلم والصلاحية → full-screen/call notification → قبول صريح → خدمة صوت/وسائط. كل سهم يمكن أن يفشل بشكل مستقل؛ enabled:true لا يختبر السلسلة كلها.

APK ووثيقة التحققبصمة الملف الحالي مختلفة عن بصمة مذكورة في أول وثيقة native-call-device-checklist؛ فيها أيضاً وصف قديم لحصة عشر رسائل.لا يمكن اعتمادها كشهادة مطابقة للنسخة الحالية. الاختلاف وحده ليس دليلاً على فساد APK.

نواقص بنيوية تزيد صعوبة التشخيص، وليست أسباباً مؤكدة لكل حادثة

  • الرسالة العامة عند فشل الإقلاع لا تعطي المستخدم سبباً، والسجل المتاح لا يحتوي stack قابلاً للتحليل.

12. ما يمنع إعلان التسليم النهائي؟

  1. مطابقة الإنتاج للكود: endpoint جاهزية FCM تحقق منه في الإنتاج، لكن تدفق الصورة المصحّح أثبت في المعاينة. يلزم دليل أن bundle/API المنشورين يحتويان الإصلاح؛ لا توجد إعادة نشر خلال هذا التقرير.
  2. تشخيص crash المستخدم: يلزم stack/network failure للحادثة نفسها. لا يكفي النص العام. السبب الجذري الآن غير محسوم.
  3. هاتف مقفول: نحتاج إثبات استقبال FCM للجهاز الصحيح، رنين، شاشة رد، قبول صريح، صوت بالاتجاهين، إنهاء وإلغاء. force-stop حالة مختلفة يجب توثيقها ولا نَعِد بتجاوز سياسات Android.
  4. APK محدد: مصدر commit وبصمة APK وتاريخ build وتثبيت فعلي موثق، بما يشمل الترقية من النسخة القديمة والصلاحيات. الملف القديم ليس إثباتاً لذلك.
  5. خصائص غير مختبرة: Delivered المستقل، الصوت/الفيديو والملفات، المجموعة، Seen/Typing، AI، الحذف التلقائي. الكود يثبت البناء؛ الاختبار وحده يثبت السلوك.
  6. فيديو الدليل: غير متوفر؛ لذلك لا يوجد تسليم مثبت للمكالمة خارج التطبيق.

هذه فجوات قبول وتوثيق وليست أمراً بتنفيذ تغييرات. لم أبدأها، ولم أطلب أسراراً جديدة أو أغير إعدادات Firebase/Android.
